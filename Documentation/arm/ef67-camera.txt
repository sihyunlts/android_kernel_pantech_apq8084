EF67S camera support
====================

Target: IM-A930S, stock firmware S0226114.

This restores stock camera GPIO mappings, EEPROM clock/power handling,
userspace command layouts, image updates, rear lens transmission and OIS
mode/information commands. DTS voltages, regulators, GPIOs and power
sequence delays are unchanged.

Stock GPIO sequence ABI
----------------------

msm_camera_init_gpio_pin_tbl at 0xc06e2714 allocates 46 bytes: fifteen u16
GPIO numbers followed by fifteen validity bytes and alignment padding.
msm_camera_power_up/down accept IDs 0 through 13. Existing IDs 0 through 8
are preserved; the additional slots are:

  ID  Name                         DT property      Stock GPIO
   9  SENSOR_GPIO_CAM0_SVDD0_EN    qcom,svdd0-en          126
  10  SENSOR_GPIO_CAM0_SVDD1_EN    (no DT mapping)
  11  SENSOR_GPIO_CAM0_AVDD_EN     qcom,avdd-en           125
  12  SENSOR_GPIO_CAM1_SVDD_EN     qcom,svdd1-en           80
  13  SENSOR_GPIO_CAM1_AVDD_EN     qcom,avdd1-en           83

The front qcom,svdd1-en property selects ID 12, not ID 10. Stock pin-table
property literals are at 0xc06e2d18 through 0xc06e2d9c. The restored table
also includes stock qcom,gpio-vio, qcom,gpio-vaf and qcom,gpio-af-pwdm.

The EEPROM parser at 0xc06e1dc0 compares sensor_gpio_cam0_avdd_en via the
literal at 0xc06e22ac and stores ID 11 at 0xc06e1fe0. DT GPIO configuration
0/1 is converted to GPIO_OUT_LOW/HIGH (0/2), as in stock.

EEPROM power sequence
---------------------

  1. Enable L17 cam_rvana at 2.85 V, 80 mA load; wait 1 ms.
  2. Enable LVS4 cam_rvio; wait 1 ms.
  3. Drive GPIO125 high; wait 3 ms.
  4. Drive GPIO36 high; wait 3 ms.
  5. Enable MCLK at 24 MHz on GPIO15; wait 3 ms.

LVS4 is a switch supply; its DT voltage 0 does not request a new voltage.
This code does not program or infer the external AVDD/SVDD output voltage.

After reading, disable MCLK, drive GPIO36 and GPIO125 low, then disable
LVS4 and L17, keeping the delays of the reversed steps. Explicit sensor
library shutdown sequences retain their supplied output levels.

Intentional differences from stock
---------------------------------

Stock shutdown at 0xc06e3550 through 0xc06e3564 uses gpio_num[config_val]
as the output value. In the stock EEPROM shutdown, config_val remains 2;
slot 2 is unmapped and zero, so the pins happen to go low. A requested low
(0), however, indexes slot 0 containing GPIO36 and would drive high.
Use config_val directly and explicitly set generated GPIO shutdown steps
low. The normal EEPROM shutdown levels match stock without relying on an
unmapped slot being zero.

Validate power-up indices, GPIO mappings and levels before enabling
supplies. GPIO requests are transactional via gpio_request_array; errors
stop startup before supplies are enabled. Regulator, clock, mux and CCI
failures unwind completed steps in reverse order. A mux configuration
failure releases its own initialization. Fix the CCI failure path's double
reference-count decrement and release CCI after a flash GPIO request fails.

Verification and remaining work
-------------------------------

Compared all twelve stock GPIO property literals/sequence IDs and the
EEPROM AVDD parser ID. Compared EEPROM, rear and front DT power properties,
GPIO numbers and regulator targets against the stock DT: all match.

Executed extracted C functions with hardware stubs to check parsing,
allocation failures, GPIO request rollback, regulator/clock/CCI failures,
invalid input rejection and explicit/generated shutdown order and levels.
The actual mux helper also passed initialization/configuration failure
checks. EF67 zImage/dtbs and the common camera subtree with EF67 disabled
built successfully.

Hardware testing with the stock ROM confirms front/rear preview, restored
colors and preview rate, still/video capture, rear focus and basic OIS
operation. The additional OIS commands below still need device testing,
as do quantitative comparisons across modes and long-term stability.

  https://www.kernel.org/doc/Documentation/gpio/gpio-legacy.txt

The VegaDevTeam msm8974 IMX214 extension also has camera power GPIO IDs,
but its header omits flash slots 7/8. Its numeric ABI cannot be copied to
EF67S; the mappings above follow the EF67S stock binary.

Stock sequential sensor-write ABI
---------------------------------

S0226114 msm_camera_cci_i2c_write_seq_table at 0xc06e02cc reads the
length at entry offset 258 and advances each entry by 260 bytes. The
data array therefore has 256 bytes, rather than the common 20-byte
layout. Restore this layout for CONFIG_MACH_APQ8084_EF67 only.

A live camera crash interrupted msm_camera_cci_i2c_write_seq with
num_byte=46844. The old 24-byte layout interpreted sensor data as the
length; the unbounded stack allocation and memset overwrote unrelated
kernel memory. Bound sequential writes before allocating, use heap
storage for the CCI register table, and allow the loop to reach 256.
Restore the client address type and release storage on failures.
QUP uses a bounded buffer and a counter capable of handling 256 bytes.

Extracted-function checks cover the common 24-byte and EF67 260-byte
layouts, valid and excessive lengths, allocation/transport errors and
address restoration. Device logs confirm valid sequential-write lengths
and stable camera preview after correcting the command layout.

Stock AXI stream update command numbers
--------------------------------------

S0226114 msm_isp_update_axi_stream at 0xc06fcb58 checks update type 4
for a pending AXI change. Its jump table at 0xc06fcc64 maps 2 to the
framedrop update, rejects 3, handles 4 as AXI configuration and 5 as a
frame request. The 100-byte update item and its fields match this tree.
For EF67, reserve UPDATE_STREAM_STATS_FRAMEDROP_PATTERN at 3 so the
existing AXI configuration/frame-request cases use stock IDs 4 and 5.
The image ioctl still rejects the reserved statistics ID, as stock does.
Other machines retain IDs 3 and 4. The built EF67 enumeration was checked.
Device logs confirm type 4 updates chroma WM dimensions correctly and
eliminates the observed ping-pong mismatch. The user confirms corrected
colors and preview rate; occasional stutter needs a stock comparison.

Stock rear lens command packing
-------------------------------

S0226114 msm_actuator_parse_i2c_params at 0xc06e4c68 sends one table entry
per input DAC register, swaps each addressed 16-bit DAC value and selects
WORD_DATA. The common implementation splits adjacent entries and keeps
the requested data size; retain that behavior for other machines.

Stock msm_actuator_init_focus at 0xc06e4f38 selects each initialization
entry's address size and restores the original client size afterward.
Writes to register 0x2c0 use WORD_DATA. Writes do not fall through into a
poll. Restore those EF67 behaviors while keeping requested delays and
propagating transport errors.

Extracted-function checks pass for both EF67 and common configurations:
DAC byte order and masked bits, per-entry address/data widths, the 0x2c0
word write, write/poll separation, transport errors and address restore.
The user confirms rear focus, colors, preview rate and OIS appear normal.
Device logs contain no VFE ping-pong mismatch or lens-write/park failure.
Those device tests did not exercise the additional OIS commands below.

Stock focus movement
--------------------

S0226114 msm_actuator_move_focus at 0xc06e6044 uses the requested target
step directly and keeps the region index unchanged. It skips the table
transfer when the target step is zero, then clears the table index.
Restore this EF67 behavior; other machines retain region transitions and
zero-target writes. Damping, unchanged-target checks and transport errors
retain their existing handling.

Extracted-function checks cover region-crossing moves, zero and unchanged
targets, invalid directions/ranges and transport failures with EF67
enabled and disabled. The user confirms focus, colors and OIS remain
normal after this follow-up. All 195 captured focus moves return zero,
with no image-buffer, lens initialization or move failure in the log.

Stock OIS mode and information commands
---------------------------------------

S0226114 msm_actuator_subdev_ioctl at 0xc06e6304 dispatches command 8 to
the OIS mode setter, 9 to information control and 10 to information read.
All use the existing 200-byte request, union offset 8 and ioctl 0xc0c856c6.
Mode is a u16 at offset 8. Information control is a u32 at offset 8;
measurement words for registers 0x86, 0x88, 0x8e and 0x90 occupy offsets
12, 14, 16 and 18. Adding these union members does not change request size.

pantech_OIS_set_mode at 0xc06e7934 stops through register 0 (byte 0),
waits 1 ms and reads status register 1 up to ten times until it is 0 or 1,
waiting 10 ms after each busy result. It writes mode register 2 (byte 5
for centering mode 0; byte 0/1 for modes 1/2), then starts through register
0 (byte 1). Preserve the register sequence and busy-wait delays. No mode
write is added to the ordinary initialization unless userspace requested
a mode. Requests between CCI initialization and lens setup are deferred
until the lens address and initialization table are successfully set.

pantech_OIS_info_ctrl at 0xc06e7620 writes byte 0/1 to register 0x80 and
updates the enabled state only after successful transmission. The read
at 0xc06e7674 preserves all output fields if information is disabled or
status register 1 is not 2. Otherwise it reads word registers in order
0x86, 0x8e, 0x88, 0x90, swaps each word's bytes and preserves the control
word. Each measurement is preceded by 1 ms; the final read also has a
following 1 ms delay. Errors preserve already-read fields as in stock.

State belongs to each actuator and is reset on initialization, powerdown
and close. Serialize close with configuration so OIS reads cannot race
CCI release. Unlike stock, reject unsupported modes/control values before
any I2C access, propagate read/mode-write errors instead of overwriting
them with a later success, report ETIMEDOUT on polling exhaustion, and
reject information access before successful transport/lens setup with
EPIPE. These checks do not change successful initialized requests.

Actual stock ARM functions and extracted C match in 29 cases covering
all three modes, delayed readiness, information toggles, idle status,
byte order, field positions and read/write failures. Separate checks
cover deferred mode requests, setup failures, failed information toggles,
shutdown/close/reopen and mutex handling. GCC 4.7 ARM actuator builds and
request-layout checks pass with EF67 enabled and disabled. These are
software checks; command 8/9/10 operation on the device is not yet verified.
